# تطوير مورد وبناء واجهاته · Development

مرجع المنتج هو [تعريف المشروع](project-brief.md)، ومراجع العرض ومنشأ الأصول في [مراجع التصميم](design-references.md). هذا الدليل يميز الموقع العام عن النظام المحلي والبحث. بناء واجهة أو اجتياز اختبارات البرمجيات لا يثبت أداء معالجة الماء أو تأهيل الذكاء ميدانيًا.

## 1. الموقع العام · Public website

استخدم Node.js **22.12 أو أحدث** وnpm من مجلد المستودع. في Windows يمكن تشغيل `npm.cmd` مباشرة من PowerShell.

لتثبيت الإصدارات الموجودة في ملف القفل:

```sh
npm ci
```

لتشغيل خادم التطوير:

```sh
npm run dev
```

العنوان: [http://127.0.0.1:4173](http://127.0.0.1:4173). يحدد [إعداد Vite](../vite.config.js) هذا المنفذ وينهي التشغيل إذا كان مشغولًا. استخدم عنوان HTTP لعرض الوحدات البرمجية والمستكشف.

المحاكي العربي في [http://127.0.0.1:4173/simulator/](http://127.0.0.1:4173/simulator/)، وله رابط ظاهر في مقدمة الصفحة الرئيسية على الحاسوب والجوال. بياناته `SIMULATED`، وليست نتائج قياس أو إثبات أداء مائي. يحافظ مساره على الموقع نفسه ولا يحتاج تطبيقًا أو خدمة استضافة أخرى.

لتشغيل اختبارات قواعد المحاكاة:

```sh
npm run check
```

لتوليد الموقع الثابت:

```sh
npm run build
```

مستوى التحقق الحالي في `check` هو اختبارات برمجية لقواعد القرار باستخدام مدخلات اختبار. يحتاج التحقق البصري والتفاعل واللغة العربية والإنجليزية والهواتف وتقليل الحركة وتعذر WebGL فحصًا في المتصفح أيضًا. لا تختبر هذه الأوامر مياهًا أو حساسًا أو صمامًا ماديًا.

## 2. النظام المحلي · Local application

لتجربة التوأم على نسخة مستودع جديدة، يلزم Python **3.10 أو أحدث** فقط:

```sh
./mawrid-system/start.command
```

افتح [http://127.0.0.1:8787/#start](http://127.0.0.1:8787/#start)، واختر «جرّب المحطة». تبقى الخدمة على loopback وتُوقف بـ`Ctrl+C`. الأصول المجمعة للواجهة والمشهد والخطوط والعرض الهندسي مرفقة؛ تشغيل المحطة الافتراضية لا يحتاج Node.js أو `npm ci` أو مكتبات ML. يحفظ `mawrid-system/var/` قاعدة التشغيل المحلية؛ لا تنشرها أو تستخدمها في اختبارات معزولة.

المشغل POSIX ولا يثبت تبعيات أو ينزل بيانات. يختار `MAWRID_PYTHON` عند تحديده، ثم `ml/gecco_baseline/.venv/bin/python` إن وجد، ثم `python3`، ويتحقق من الحد الأدنى للإصدار. لتعيين مفسر معين: `MAWRID_PYTHON=/path/to/python3 ./mawrid-system/start.command`. ويمكن تشغيل الخدمة مباشرةً بـ`python3 -B mawrid-system/server/main.py`؛ على Windows استخدم `py -3 -B mawrid-system/server/main.py` مع Python مؤهل.

يوجد اختلاف مقصود بين الأسطح الثلاثة:

| السطح | الخدمة أو المسار | مصدر الحالة |
|---|---|---|
| الموقع العام ومحاكيه التعليمي | `4173` أثناء التطوير، أو GitHub Pages | منطق محاكاة مستقل في `web/` |
| تجربة المحطة المحلية | `8787/#plant` والمشهد `/plant3d/` | لقطات التوأم من خدمة Python وقاعدة SQLite |
| العرض الهندسي | `/viewer/` من `mawrid-final/dist/` المرفق | مستكشف تصميم مستقل؛ لا يتحكم بالمحطة |

لا تنشر GitHub Pages خدمة Python ولا تمنح زائر الموقع وصولًا إلى قاعدة جهازك. رفع الكود أو تشغيل الخادم لا يوصل حساسًا أو صمامًا ماديًا.

### العرض التلقائي UX V8

يبدأ العرض بإجراء صريح، ويشرح ثماني مراحل عبر `water-journey.js`. يدير `presentation.js` وقت القراءة، بينما ينسق `app.js` إقرار وصول الكاميرا من `plant3d/main.js`. يبدأ العد بعد الوصول؛ المدد الحالية 24، 21، 26، 22، 27، 22، 24، 24 ثانية، بمجموع 190 ثانية قراءة وحركة كاميرا تقارب 1.1 ثانية لكل مرحلة.

إيقاف العرض يحفظ المهلة ولا يوقف الساعة الهيدروليكية. التصفح والتفاصيل والتحكم بالكاميرا والانقطاع وحالات المحطة تقطع العرض وتحتاج متابعة صريحة. الانتقال التلقائي لا يستدعي حقن الأعطال أو فتح الصمامات؛ النهاية تعود إلى العرض العام. البديل النصي يحافظ على قابلية الشرح عند تعذر المجسم. هذه رحلة تعليمية، لا حساب زمن مكوث أو تفاعل كيميائي.

### تعديل المصدر وإعادة بناء المحلي

| المصدر | الوظيفة |
|---|---|
| `mawrid-system/server/` | HTTP، التخزين، محرك التوأم وحدود المصادر |
| `mawrid-system/client/` | الواجهة العربية وحالة التجربة والعرض والرسوم |
| `mawrid-system/plant3d/` | مصدر المشهد التشغيلي والكاميرا والمحول |
| `mawrid-system/client/plant3d/` | أصول المشهد المجمعة التي تخدمها الخدمة |
| `mawrid-system/edge/` | جامع قراءات محلي وطابور SQLite دائم؛ ليس مولد قياسات |

عند تطوير المصدر، ثبت الأدوات المقفلة من الجذر ومن مجلد العرض الهندسي الذي تشاركه أدوات البناء:

```sh
npm ci
npm --prefix mawrid-final ci
```

بعد تحرير ملفات مصدر الواجهة أو المشهد، شغّل بناء الجزء المتأثر مع **مسار إثبات جديد**؛ ترفض الأدوات استبدال دليل سابق:

```sh
node mawrid-system/build-client.mjs --proof output/mawrid-system/client-build-next.json
python3 mawrid-system/plant3d/build-proof.py --proof output/mawrid-system/plant3d-build-next.json
```

الأمر الأول يجمع الوحدات في ملف JavaScript كلاسيكي مؤجل ذي اسم يحمل بصمة المحتوى، ويحدث وسم الدخول في `client/index.html`. الثاني يبني المشهد ويختبره ويسجل بصمات المصادر والأصول. احتفظ بالمصدر والأصل المولد وإثباته متطابقة. لا تعدل ملفًا مولدًا وحده، ولا تُعد استخدام دليل تاريخي لإثبات مصادر تغيرت لاحقًا. `npm run build` في الجذر يبني الموقع العام فقط.

لإعادة بناء العرض الهندسي المستقل بعد تعديل مصدره، شغّل `npm --prefix mawrid-final run verify` ثم `npm --prefix mawrid-final run build`. تُرفق مخرجات `mawrid-final/dist/` في التسليم حتى يعمل `/viewer/` دون أدوات التطوير. هذه الخطوة منفصلة عن بناء المشهد التشغيلي `plant3d` وعن ملف الواجهة الرئيسي.

### اختبارات محلية معزولة

من جذر المستودع، دون تشغيل تدريب أو لمس قاعدة المشغل:

```sh
python3 -B -m unittest discover -s mawrid-system/server -t mawrid-system -p 'test_*.py'
python3 -B -m unittest discover -s mawrid-system/edge -t mawrid-system
node mawrid-system/client/test-client.mjs
node mawrid-system/client/test-plant.mjs
node mawrid-system/client/test-experience-state.mjs
node mawrid-system/client/test-water-journey.mjs
node mawrid-system/client/test-presentation.mjs
```

بعد تثبيت تبعيات تطوير المشهد:

```sh
node --test mawrid-system/plant3d/test-*.mjs
```

اختبارات المنطق لا ترسم متصفحًا. افحص التشغيل الصريح، الرحلة التلقائية كاملة، الإيقاف والمتابعة، مقاطعة الكاميرا والتفاصيل، الإنهاء دون عطل تلقائي، التنقل بلوحة المفاتيح، العرض الضيق وتقليل الحركة وتعذر WebGL والاتصال. سجل الأبعاد والنطاق والقيود؛ لا تسمّ هذه الفحوص دراسة استخدام أو اعتماد إتاحة.

[دليل UX V8](../output/mawrid-system/ux-v8/verification.json) يربط الاختبارات وبناء الواجهة والمشهد وفحص المتصفح. أرقام كل إصدار تخص بصماته ونطاقه؛ لا تجمعها في رقم تحقق مائي أو ادعاء دقة ML.

### البحث الاختياري وخصوصية السجلات

مختبر البيانات العامة ليس متطلبًا لتشغيل التوأم. يحتاج إعادة العرض البحثية المؤهلة كودًا وبيانات وحزمة نموذج موثوقة وتبعيات متوافقة، وتتحقق الخدمة من حالة الإتاحة والبصمات. لا تُحمّل حزمًا مسلسلة من مصدر غير موثوق. لا تعمل V9 على ماء التوأم أو مخطط قراءات الجهاز، ولا تمنح الحالة الافتراضية درجة ML مصطنعة عند غياب الحزمة.

اتبع [بطاقة النموذج](data-and-model-card.md) وملفات المصدر والبروتوكول المعني لإعادة تجربة بعينها؛ تثبيت مكتبات الموقع لا يثبت توافق بيئة البحث أو يعيد نتائجها. البيانات العامة خاضعة لتراخيص مصادرها. استبعد من Git البيئات، قواعد البيانات، التنزيلات، حزم النماذج غير المعتمدة للنشر، الملفات المرجعية الخاصة والاتصالات. يمكن نشر تقارير منقحة وأمثلة مصطنعة موسومة بعد المراجعة.

يوثق [دليل أصول البحث](research-assets.md) نطاق التقارير المنتقاة وخطوات الحصول على البيانات وحزمة V9 الاختيارية لإصدار v0.3.0. تنزيل الحزمة ليس تدريبًا جديدًا أو ترقية للنموذج، ولا يزيل قيود التأهيل أو يحول التوأم إلى مصدر ML مؤهل.

## 4. المصدر ومخرجات GitHub Pages

يستخدم Vite الجذر `web/` وروابط نسبية (`base: './'`)، مع مدخلي HTML للصفحة الرئيسية والمحاكي. يكتب البناء إلى `.site-build/`، ثم ينفذ [scripts/build-site.mjs](../scripts/build-site.mjs) الخطوات التالية:

1. نسخ ملفات JavaScript وCSS والأصول المجمعة إلى `assets/app/` في جذر المستودع.
2. كتابة الصفحة المجمعة في [index.html](../index.html) بالجذر.
3. كتابة صفحة المحاكي المجمعة في `simulator/index.html`، بروابط أصول نسبية تناسب المسار الفرعي للمشروع.

| المسار | حالته |
|---|---|
| `web/index.html` و`web/simulator/index.html` و`web/src/` | مصدر قابل للتعديل |
| `.site-build/` | مخرج بناء وسيط محلي يتجاهله Git |
| `index.html` و`simulator/index.html` و`assets/app/` | مخرجات ثابتة لخدمة الموقع من جذر المستودع |
| `node_modules/` | تبعيات محلية يتجاهلها Git |

إعداد التسليم الموثق للموقع هو **الفرع `main` والمجلد الجذر `/`**، بنمط البناء من الفرع؛ تحقق من إعداد الاستضافة الحالي قبل النشر. لهذا تُحفظ مخرجات الموقع الثابت في الجذر؛ `web/` يحتوي المصدر. بعد نجاح بناء Vite، يتحقق السكربت من المسار المطلق للمجلد المولد `assets/app` ويستبدل محتوياته لإزالة ملفات البناء القديمة ذات الأسماء المجزأة. ينسخ الملفات الجديدة ثم يكتب `index.html` و`simulator/index.html`؛ ملفات الشعارات والصور والخطوط الأصلية تقع خارج هذا المجلد. عنوان المحاكي بعد نشره على الموقع الحالي هو `https://sultalfaifi.com/mawrid-water-reuse/simulator/`؛ وجود المسار في مخرجات البناء محليًا لا يؤكد نشره الحي.

`npm.cmd run build` عملية محلية. لا يرفع إلى GitHub ولا يغير إعداد Pages ولا ينشر تحديثًا. عند تسليم تغيير قابل للنشر، يلزم أن تطابق الصفحة المجمعة وأصولها نسخة المصدر المراد تسليمها. نشر النسخة والتحقق من الرابط الحي مرحلتان منفصلتان عن البناء المحلي.

## 5. إضافة أو تغيير محتوى

- حدّث [مرجع المشروع](project-brief.md) قبل توسيع المصدر أو الاستخدام أو الادعاء.
- حافظ على تكافؤ معنى نصوص العربية والإنجليزية في `content.js`؛ العربية افتراضية وباتجاه RTL.
- عرّف المحاكاة أو الهدف أو النتيجة وفق [سجل الأدلة](evidence-register.md).
- احتفظ بتراخيص الخطوط ووثيقة منشأ الصورة مع الأصول.
- بعد تغيير الوثائق أو الأصول أو الكود، أعد البناء حتى تتوافق ملفات الجذر مع المصدر.

## 6. تجربة المحكّم داخل المتصفح

المسار `experience/` مدخل مستقل للمحاكاة الثلاثية الأبعاد، يعمل من استضافة ملفات ثابتة دون خادم Python. تبقى الخدمة المحلية وقاعدة SQLite والبحث كما هي. دليل [تجربة المتصفح](browser-demo.md) يوضح المصدر والبناء والاختبارات وحدود المقارنة بالمحرك المحلي. لا يمثل هذا المسار استضافة للخدمة المحلية أو استدلال ML أو اتصالًا بعتاد.

يظهر رابط التجربة في مقدمة الموقع وREADME. يظل المحاكي التعليمي السابق متاحًا في `simulator/`، وتبقى أدلته ونسخه محفوظة. تحقّق من المسار الفرعي `/mawrid-water-reuse/experience/` عند اختبار النشر؛ نجاح الصفحة على الجذر المحلي وحده لا يكفي للتحقق من الروابط.
