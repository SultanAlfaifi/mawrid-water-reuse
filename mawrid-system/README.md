# مورد — نظام التشغيل المحلي

واجهة عربية للتعرّف على مورد وتجربة منشأته الافتراضية، مع دليل للأجزاء، وسجل دائم للقراءات والأحداث، ومختبر منفصل لنموذج كشف الشذوذ V9، وجامع محلي لملفات قياسات الجهاز. يعمل التطبيق والخطوط والأصول محليًا، وتحفظ SQLite السجلات والإعدادات بين مرات التشغيل.

## التشغيل المحلي

افتح `start.command` بالنقر المزدوج، أو نفّذ من جذر المشروع:

```sh
./mawrid-system/start.command
```

افتح [مورد المحلي](http://127.0.0.1:8787/#start). صفحة **تعرّف على مورد** `#start` هي البداية الافتراضية. اختر **«جرّب المحطة» → «تشغيل وعرض تلقائي»** لرحلة الماء الكاملة، أو استخدم التشغيل اليدوي. إذا كانت المحاكاة تعمل يظهر «ابدأ العرض التلقائي». فتح الصفحة وحده لا يبدأ جلسة أو إعادة عرض بيانات عامة؛ بدء العرض من محطة غير مشغلة ينشئ جلسة افتراضية واضحة المصدر بإجراء المستخدم. لإيقاف الخدمة اضغط Ctrl+C في نافذة التشغيل.

يلزم **Python 3.10 أو أحدث**. يفضل المشغل المفسر المحدد في `MAWRID_PYTHON`، ثم بيئة `ml/gecco_baseline/.venv` الموجودة إن توفرت، ثم `python3`، ويتحقق من الإصدار. لا يثبت مكتبات أو يحمل بيانات؛ تحتاج المحطة الافتراضية وخدمة HTTP وSQLite مكتبة Python القياسية فقط. الخدمة محصورة في loopback على هذا الجهاز.

يمكن تشغيل الخادم مباشرةً بـ`python3 -B mawrid-system/server/main.py` من جذر المستودع؛ على Windows استخدم `py -3 -B mawrid-system/server/main.py` مع الإصدار المؤهل. تأتي حزم الواجهة و`client/plant3d/` و`mawrid-final/dist/` والخطوط المحلية مرفقة؛ لا يلزم Node.js للاستخدام. مختبر البحث اختياري، ويعرض عدم الإتاحة بوضوح إذا غابت البيانات أو الحزمة المؤهلة. يوضح [دليل أصول البحث](../docs/research-assets.md) حزمة V9 الاختيارية لإصدار v0.3.0.

## رحلة الاستخدام وهوية المشروع

| المسار | ما يعرضه |
| --- | --- |
| `#start` — تعرّف على مورد | مصدر الماء واستخدامه، والفرق بين وحدة مورد المتكاملة وصندوق مورد المضاف إلى محطة قائمة. |
| `#plant` — جرّب المحطة | مجسم ثلاثي الأبعاد مضمّن، وضوابط التشغيل، وحالة الماء والمعدات. |
| `#components` — أجزاء المحطة | دليل **34 جزءًا** يشرح دور كل جزء وتمثيله وحدود محاكاته. |
| `#technology` — البرمجة والذكاء والأدلة | شرح تدفق البيانات والكود خطوة بخطوة، وفصل قواعد التوأم عن نموذج ML وأدلة اختباره. |
| `#follow` — المتابعة والسجل | الحالة وسببها والقراءات والأحداث والسجلات. |

هوية مورد في هذه الواجهة هي **مياه الوضوء والمغاسل إلى ري المسطحات الخضراء**، بمنتجين مقترحين: وحدة معالجة متكاملة، وصندوق مراقبة وتحكم لمحطة قائمة. ثُبتت الهوية من `mawrid_full_description.md`؛ وعند تعارض التفاصيل التقنية أو الأسعار يُقدّم مرجع المستخدم `مورد-محطة-المياه-الرمادية.html`. تمثل هذه الملفات وصف التصميم، ولا تجعل الأسعار عروض توريد أو مواصفات الأداء نتائج متحققة. تسجل [مصفوفة المطابقة](../output/mawrid-system/ux-v5/requirements-review.json) ما نُفذ وما بقي تمثيلًا تصميميًا.

## غرفة التشغيل والتوأم الرقمي

يعرض المجسم المصفاة، وخزان الخام المدفون بمقطع تعليمي ومضخته الغاطسة، والجرعة الأولية DP101، ومرشح الوسائط، وجرعة إزالة الكلور DP102، ومرشح الكربون، والخراطيش CF101، وضبط pH بالجرعة DP103، والجرعة النهائية DP104، ولوحة قياسات الجودة، وصمام المطابقة XV101، وUV، وخزان المنتج الأفقي، ومضخة الري وصمامه. تظهر أيضًا لوحة PLC، وخط العودة، وحجرة الكربون التجريبية. اضغط الجهاز، أو اختره بلوحة المفاتيح، لعرض تفاصيله. مستويات الخزانات والعدادات تأتي من محرك المحاكاة؛ لا تولّد الواجهة قراءات أو درجات ذكاء اصطناعي.

افتراضات هذه التجربة البرمجية:

- خزانان بسعة **5000 لتر لكل خزان**، يبدأ الخام عند **3000 لتر** والمنتج عند **2000 لتر**.
- معدل الدخول والتغذية والمنتج والري في التشغيل الاعتيادي **1000 لتر/ساعة** لكل منها، مع تقييد التدفقات بالمخزون. توافق هذه التدفقات افتراض توضيحي؛ ليس تنبؤًا بطلب الري أو توفر مياه المصدر.
- السعة الاسمية **15 م³/يوم عند 15 ساعة تشغيل يوميًا**. لا يطبق المحرك جدول دوام يوميًا أو توقفًا تلقائيًا بعد 15 ساعة؛ استمرار التشغيل الافتراضي 24 ساعة بمعدل ثابت ينقل 24 م³.
- الانتقال الحجمي الاعتيادي من الخام إلى المنتج كامل، **دون رفض مستمر بنسبة 20%**؛ لا توجد مرحلة RO. يُبقي API حقل `drain_lpm` للتوافق، وقيمته صفر في التشغيل الاعتيادي. هذا حساب حجم، لا افتراض إزالة تلوث أو كفاءة معالجة 100%.
- الغسيل العكسي يسحب من مخزون المنتج بمعدل مفترض **65 لتر/دقيقة**، المقابل لـ3.9 م³/ساعة في المرجع، ويُحد بالماء المتاح. ليس ذلك اعتمادًا لحجم المضخة أو كفاءة الغسيل. يحاسب المحرك الغسيل والفائض والري والمخزون كلًا على حدة.
- خط العودة تمثيل تصميمي، و`recirculation_lpm=0` في المحاكاة الحالية. الاحتجاز والتوقف اليدوي وفقد الكهرباء توقف التدفقات؛ لا يُفترض تحويل بالجاذبية أو ضخ خفي إلى خزان الخام.
- إشارات الجودة والضغط توضيحية وحتمية. الجرعات الأربع وUV وحجرة الكربون التجريبية ممثلة تصميميًا دون محاكاة كيميائية أو اختلاق قياسات إضافية؛ لا يثبت العرض كفاءة تعقيم أو إزالة ملوثات أو ملاءمة ميدانية.

تعرض البطاقات تدفق **المعالجة** بوحدة L/min، والري المحاكى بوحدة L، وفرق ضغط المرشح بوحدة bar، ووضع العملية. قناة `flow_lpm` في سجل الحساسات تخص **تدفق الري الافتراضي**؛ تدفق تغذية المعالجة محفوظ منفصلًا داخل `virtual_plant.flow.treatment_lpm`. فرق ضغط الوسائط هو `p1_bar − p2_bar`، والكربون `p2_bar − p3_bar`، والخراطيش `p3_bar − p4_bar`.

### الساعة والضوابط

يحرك عامل خلفي الساعة الافتراضية بمقدار 1 أو 10 أو 30 ثانية افتراضية لكل نبضة تشغيل، وفق السرعة المختارة. تقرأ الواجهة الحالة كل ثانيتين؛ طلب `GET /api/state` لا يقدم المحاكاة. تعليق الجهاز لا يُملأ بخطوات أو قراءات مختلقة.

| الإجراء | النتيجة داخل التوأم |
| --- | --- |
| تلقائي | تُحسب إتاحة المعالجة والري من القواعد الثابتة وحالة المخزون. |
| استعداد | تتوقف التدفقات، وتستمر الساعة الافتراضية إذا لم تكن موقوفة مؤقتًا. |
| غسيل عكسي | يُسحب ماء الغسيل من الخزان المعالج إلى مسار الصرف؛ الري مغلق. |
| إيقاف المحاكاة مؤقتًا | تتوقف الساعة وتراكم الأحجام؛ تبقى آخر حالة تشغيل معروضة. «متابعة المحاكاة» يستأنف الساعة. |
| تثبيت الاحتجاز من الإعدادات | يُحفظ الطلب اليدوي، وتتوقف المضخات والتدفقات الافتراضية وتُغلق الصمامات، وتتوقف الجلسة. |
| إزالة الطلب اليدوي | يُعاد حساب حالة التوأم وفق القواعد، وتظل الساعة متوقفة حتى اختيار المتابعة. لا يصدر أمر إلى عتاد. |

سيناريوهات الاختبار: التشغيل الاعتيادي، وارتفاع العكارة، وانقطاع قراءة حساس، وانسداد المرشح، وانقطاع الكهرباء، وتعطل صمام الري في وضع الإغلاق. تظهر الاستجابة بحالات **معالجة وري / احتجاز / استعداد / غسيل عكسي**، وتُحفظ الأوامر والانتقالات في سجل الأحداث. زر «تم الاطلاع» يوثّق مراجعة الحدث.

حماية التوأم تعتمد قواعد تشغيل تجريبية ثابتة، ولا تستخدم تصنيف ML لهذه السيناريوهات. إعدادات حدود قراءات الجهاز في صفحة الإعدادات لا تغيّر ثوابت محرك التوأم. الصمامات المعروضة في غرفة التشغيل افتراضية؛ `app.hardware_connected=false` و`overview.valve_state=closed` يصفان حالة الربط المادي. المجسم الأصلي تحت `/viewer/` **عرض هندسي** مستقل، دون ربط لحظي بحالة التوأم.

## العرض التشغيلي ثلاثي الأبعاد

صفحة **جرّب المحطة** `#plant` تعرض رحلة ماء من ثماني مراحل: التجميع، الوسائط، الكربون، الترشيح الدقيق والجرعات النهائية، التحقق، موضع UV الاختياري، خزان المنتج، والري. في كل مرحلة بطاقة قصيرة للوظيفة والفائدة، وإضاءة للمعدات وخطها، وزر تالٍ ورجوع بسيط. ثم يظهر اختبار انقطاع الحساس وإزالة العطل. ترتيب الشرح ليس زمن عبور الماء أو حساب فعالية معالجة؛ أزرار الرحلة لا تغيّر تشغيل المحطة. يحتفظ التوقف والاحتجاز والعطل الموجود بأولويته؛ لا تسجّل الواجهة نجاحًا بناءً على النقر وحده. زر الإيقاف المؤقت ظاهر أسفل المشهد. القراءات والخيارات في «التفاصيل»، وشرح الأجزاء والبرمجة والذكاء متاح من داخلها. إلغاء الاحتجاز اليدوي مستقل عن استئناف التشغيل.

المشهد الهادئ المضمّن `/plant3d/index.html?embed=1&simple=1` يضيء معدات المرحلة ومسارها بلون تعليمي مستقل، ويعرض أسماء المرحلة فقط دون عدادات متكررة. ترتبط حركة الأسهم بالتدفق الفعلي في المحاكاة، وتتوقف عند الإيقاف أو انقطاع الاتصال. الضغط على جزء يفتح مهمته وفائدته فقط. [العرض المستقل المفصل](http://127.0.0.1:8787/plant3d/index.html) باقٍ. يقرأ المجسم الحالة كل ثانيتين؛ فتح الصفحة أو تفاصيلها لا يبدأ جلسة ولا يرسل أمرًا.

الماء داخل الخزانين ومؤشرات المضخات ومسارات التغذية والمنتج والري والغسيل تأتي من لقطة المحرك نفسها. تبقى خطوط الجرعات والعودة والحجرة التجريبية تمثيلات تصميمية بلا تدفق محسوب. تُعرض إشارة الصمام المستلمة مستقلة عن أمره، والقراءة المفقودة تبقى غير متاحة. عند إيقاف ساعة المحاكاة يتوقف التحريك؛ انقطاع الاتصال يعرض آخر لقطة بعلامة واضحة، ولا يغيّر وضع الصمام إلى «مغلق» مختلق. تبديل المصدر يمسح بيانات الجلسة السابقة.

هذا تصوير تشغيلي افتراضي بخزانين 5000 لتر ومعدل تغذية 1000 لتر/ساعة، وليس مخطط تصنيع أو نموذج معالجة كيميائية. العرض الهندسي الأصلي تحت `/viewer/` محفوظ مستقلًا بملفاته الـ45؛ تحديث المشهد التشغيلي لا يعدّل ذلك العرض. لا يعمل مصنف ML على ماء التوأم ولا يمنح العرض صلاحية لعتاد.

الأصول المجمعة محفوظة في `client/plant3d/` ولا تحتاج إنترنت أو بناء عند الاستخدام. مصدرها في `plant3d/`. لإعادة البناء بعد تحرير المصدر اختر ملف دليل جديدًا: `python3 mawrid-system/plant3d/build-proof.py --proof output/mawrid-system/plant3d-build-next.json` من جذر المشروع؛ تُستخدم مكتبات Three.js وVite والخطوط المثبتة محليًا في `mawrid-final/node_modules`.

اجتاز [بناء ux-v5 / r6](../output/mawrid-system/ux-v5/plant3d-build-r6.json) **21 اختبارًا مصطنعًا**، وسجّل بصمات 17 ملف مصدر و1405 ملفات مكتبات محلية و24 أصل بناء. واجتاز [تحقق HTTP/SQLite ومحول العرض](../output/mawrid-system/ux-v5/plant3d-integration-r6/verification.json) **17 لقطة و887 فحصًا**. قاعدة الاختبار مؤقتة ولم تُفتح قاعدة المشغل أو يُحمّل ML؛ وظلت ملفات العرض الهندسي الأصلية الـ45 مطابقة لبصماتها. يغطي دليل المتصفح `output/mawrid-system/ux-v5/browser-verification.json` الجولة والأعطال والتوقف والبحث وشرح التقنية، وفحص عرض ضيق وآخر مكتبي. هذا تحقق وظيفي، وليس دراسة استخدام مع كل فئات الجمهور أو اعتماد إتاحة. تبقى أدلة الإصدارات السابقة محفوظة بنطاقاتها الأصلية.

## مختبر الذكاء على البيانات العامة

من «نظرة عامة» أو «مختبر الذكاء»، اختر بدء جلسة ثم مصدر GECCO لجودة المياه أو WaterHub للضغط، وفعّل إقرار النطاق البحثي. استخدم قراءة واحدة أو التشغيل المتتابع؛ كل خطوة تحسب الاستدلال الحقيقي من قراءات المصدر، دون استخدام وسوم الاختبار في الاستدلال.

النموذج المتصل حاليًا **V9**. ثبت تطابق محول الحساب المتسلسل في أول 1600 قراءة مؤهلة من كل مصدر، ويتحقق التحميل من بصمات الكود والبيانات والتدقيق والحزمة الموثوقة. لا يمكن رفع حزمة نموذج أو اختيار مسار ملف من الواجهة. الإصدارات التجريبية الأخرى منفصلة، ولا توجد ترقية صامتة في التطبيق.

في التقييم التطويري عبر 19 فترة اكتشف V9 **113 من 399 حدثًا**، مع **237 مقطع إنذار كاذب و478 دقيقة كاذبة**. اكتشف V6 المرجعي 115 حدثًا مع 298 مقطعًا كاذبًا؛ معيار تقليل الإنذارات مع الاحتفاظ بكل الأحداث **لم يتحقق**. تقرير التقييم متاح تحت `/evidence/gecco-v9/report.html`.

أحدث تجربة منفصلة هي [سياسة V15](../output/ml/gecco-v15/report.html): اكتملت الفترات الـ19 واجتازت إعادة سياسة القرار والقياسات التدقيق المستقل، مع ثبات النماذج ودرجاتها. انتهت كل الحالات إلى V8 دون تعديل: 117/399 حدثًا، و235 مقطعًا كاذبًا، و475 دقيقة كاذبة؛ بقي حدثان مفقودان من اتحاد 119، ولم يثبت تحسن جديد أمام V8. لا ترقية إلى التطبيق أو ربط بالمحاكي. [بطاقة النموذج](../docs/data-and-model-card.md) تفصل نتائج التطوير عن تأهيل V9 البرمجي المحدود، وعن تحقق العرض الافتراضي، وعن التجربة الميدانية غير المنفذة. تقرير [V14 السابق](../output/ml/gecco-v14/report.html) محفوظ للمقارنة.

تحضير V16 وصل إلى 136 اختبارًا مصطنعًا، لكن تجميده لم يكتمل ولم يبدأ التدريب الفعلي. أُعطيت أولوية العمل لتحسين تجربة التوأم الرقمي؛ لا تمثل اختبارات التحضير نتيجة نموذج جديدة.

الدرجة ترتيب لشذوذ الحدث، وليست احتمال سلامة معايرًا أو إثبات ثقة لكل حساس. لم تثبت هذه التجارب تصنيف أعطال الحساسات الخمسة، أو ملاءمة مياه الوضوء، أو زمن الاستجابة على Raspberry Pi. المصادر العامة سبق كشفها في التطوير؛ لا تمثل تحققًا ميدانيًا مستقلًا. يظهر ML غير متاح لمصدر التوأم ولقراءات الجهاز، وتبقى محاكاة العملية منفصلة عن تقييمه.

تحتفظ إعادة العرض بساعة المصدر الأصلية: ملف GECCO المسماة 2019 يتضمن تواريخ 2017. اختصار انتظار العرض لا يغيّر فواصل المصدر البالغة 60 ثانية. تُستبعد أول 120 قراءة قبل بناء الخصائص، ثم تُطبق تهيئة السياق والإتاحة الأصلية؛ القيم المفقودة تبقى مفقودة. وحدات GECCO الأصلية تشمل الموصلية S/m والعكارة FNU وPFM بوحدة Hz، وفق [جدول قنوات التحدي](https://www.th-koeln.de/mam/downloads/deutsch/hochschule/fakultaeten/informatik_und_ingenieurwissenschaften/rulesgeccoic2019.pdf).

## جامع القراءات المحلي

ابدأ مصدر **قراءات جهاز عبر API**، ثم افتح الإعدادات وانسخ UUID من بطاقة «ربط جامع القراءات». لا يظهر زر النسخ إلا لجلسة API الحالية المطابقة والجاهزة. تعرض البطاقة آخر جهاز ووقت استلام وإيصال قراءة؛ وصول الإيصال يثبت حفظ الرسالة برمجيًا.

اتبع [دليل الجامع](edge/README.md) لتهيئة ملف JSONL وتشغيل الاستيراد والإرسال. الجامع يحفظ كل سطر في طابور SQLite دائم أولًا، ويولّد `measurement_id` UUID ثابتًا، ويثبّت `session_id`. يُقرّ الإرسال فقط بعد إيصال يطابق الهويتين ويحمل `reading_id` صالحًا. إذا ضاع الرد بعد حفظ الخادم، تعاد الرسالة بالهوية نفسها ويُعاد إيصالها دون إنشاء قراءة ثانية. لا يغيّر الجامع جلسة قراءة معلقة تلقائيًا عند تبديل مصدر التطبيق.

كل سطر يتضمن وقت المصدر مع المنطقة الزمنية، و`device_id`، والقنوات الأربع: `turbidity` بوحدة NTU، و`ph`، و`chlorine` بوحدة mg/L، و`flow_lpm` بوحدة L/min. أرسل `null` للفقد؛ الكلور قياس مباشر، ولا يُستنتج من ORP. استخدم `--input-kind measured` للقياسات المقاسة، أو `fixture` لملف اختبار بهوية جهاز تبدأ بـ`fixture-` أو `fixture:`. لا ينتج الجامع قياسات ولا ينشئ جلسات.

تطبق هذه القنوات حدود الإعدادات التجريبية فقط؛ نموذج GECCO/WaterHub غير مؤهل لمخططها. يعمل الجامع على الجهاز نفسه، دون فتح منفذ للشبكة أو اتصال تلقائي بمتحكم مادي.

## السجل ومصدر كل قراءة

يحفظ مجلد `var/` قاعدة SQLite. بدء جلسة جديدة يبقي السجل السابق. بعد إعادة تشغيل الخدمة يلزم بدء جلسة جديدة لتهيئة النموذج أو التوأم؛ تحفظ السجلات والأوامر والإعدادات، ولا تُستأنف الحالة الزمنية للمحرك من موضع قديم بلا سياقها.

يتضمن تصدير القراءات CSV معرّف الجلسة والمصدر، ووقت المصدر والاستلام، وهوية الجهاز والقياس عند وجودهما، والقنوات، وقرار البرنامج وسببه. يوضح `provenance_mode` مصدر البيانات:

| القيمة | مصدر السجل |
| --- | --- |
| `digital_twin` | حسابات المنشأة الافتراضية. يحوي عمود `virtual_plant` لقطة JSON كاملة للخزانات والتدفقات والأحجام والمعدات والقواعد والافتراضات وقت حفظ القراءة. |
| `qualified_public_replay` | إعادة عرض بيانات عامة مع استدلال V9 الحقيقي. |
| `telemetry_ml_unavailable` | رسالة قراءات جهاز، مع بقاء ML غير مؤهل؛ هويات `fixture` تميز اختبارات النقل المصطنعة. |

يمكن تصدير القراءات والأحداث من الواجهة، وتنزيل ملخص JSON من `/api/report`. أحجام المحاكاة محفوظة باسمها وبمصدرها؛ `measured_irrigation_liters` يظل غير مقاس، ولا تُشتق منه مطالبة بوفر ميداني. نجاح النقل أو النموذج برمجيًا لا يمثل اعتمادًا للمنظومة المائية.

## الاختبارات وأدلة التنفيذ

العقد في [CONTRACT.json](CONTRACT.json). الاختبارات المصطنعة تشمل اتزان الأحجام، وضوابط المحاكاة، وعزل المصادر، والاستجابات المتأخرة، وثبات جلسة القياس، واستعادة الإرسال والإيصالات. اجتازت مجموعة الخادم النهائية 60 اختبارًا، ومجموعة الواجهة 34 مجموعة فحص؛ سجلاتها في `output/mawrid-system/ux-v5/`. تبقى نتائجها منفصلة عن اختبارات البناء والمحول والمتصفح.

من جذر المشروع:

```sh
python3 -B -m unittest discover -s mawrid-system/server -t mawrid-system -p 'test_*.py'
node mawrid-system/client/test-client.mjs
node mawrid-system/client/test-plant.mjs
node mawrid-system/client/test-experience-state.mjs
node mawrid-system/client/test-water-journey.mjs
node mawrid-system/client/test-presentation.mjs
python3 -B -m unittest discover -s mawrid-system/edge -t mawrid-system -v
```

تستخدم اختبارات الخدمة والجامع بيانات اختبار وقواعد معزولة. يحتاج اختبار مصدر المجسم تبعيات التطوير المقفلة كما في [دليل التطوير](../docs/development.md). أما تحقق الاستدلال الحقيقي أدناه فيحتاج أصول البحث المؤهلة وبيئتها؛ لا يعد غيابها فشلًا للمحطة الافتراضية.

أدلة التنفيذ المحفوظة اجتازت نطاقاتها المحددة:

- [استدلال المصادر العامة integration-v3.json](../output/mawrid-system/integration-v3.json): استدلال فعلي عبر HTTP وحفظ SQLite، بواقع 1600 قراءة من GECCO و1600 من WaterHub. تطابقت القرارات ووقت المصدر والقيم، وكان أكبر فرق في الدرجة المحفوظة **صفرًا** لكل مصدر. يشمل الدليل بقاء السجلات بعد إعادة تشغيل الخدمة.
- [نقل القياسات edge-integration-v3.json](../output/mawrid-system/edge-integration-v3.json): **55 من 55 فحصًا** ناجحًا على قياسات اختبار موسومة، تشمل الحفظ والإيصالات وإعادة المحاولة وثبات الجلسة. هذا تحقق من النقل والحفظ، دون جهاز مادي أو تقييم جودة مياه.
- [التوأم plant-integration-ux-v5.json](../output/mawrid-system/plant-integration-ux-v5.json): **12 مجموعة تحقق** ناجحة عبر HTTP وSQLite مؤقتة، مع حفظ **133 قراءة افتراضية وفحص لقطاتها الكاملة**. تحققت ساعة تشغيل حتمية بدخول وري 1000 لتر لكل منهما ومخزون ثابت 5000 لتر، دون رفض اعتيادي، واختُبرت نبضة العامل الخلفي الحقيقية. لم يُحمّل ML أو يُستخدم عتاد.

تتضمن ملفات الأدلة بصمات الكود الذي نُفذ؛ اختبارات العرض منفصلة عن إثبات تطابق حساب النموذج. يبقى [دليل integration-v2 السابق](../output/mawrid-system/integration-v2.json) محفوظًا للمراجعة التاريخية. لا تمثل هذه النتائج قبولًا إحصائيًا جديدًا لـV9 أو تجربة ميدانية.

لإعادة اختبار المصادر العامة بقاعدة منفصلة وملف نتيجة جديد:

```sh
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 ml/gecco_baseline/.venv/bin/python -B mawrid-system/scripts/verify_actual.py --output output/mawrid-system/integration-new.json
```

تحسين تجربة UX V6: اختبارات الواجهة 45 مجموعة، وحالة التجربة 20 حالة مصطنعة، وبناء المجسم 21 اختبارًا. أدلة الفحص واللقطات في `output/mawrid-system/ux-v6/`؛ فحص متصفح فعلي للتشغيل والعطل والإزالة والتوقف والتفاصيل، وعرض جوال ومكتبي. ليست دراسة استخدام أو إثبات أداء ميداني.

تحسين رحلة الماء UX V7: شرح متدرج من ثماني مراحل مع تمييز المعدات ومسارها. اجتازت 52 مجموعة واجهة، و22 حالة تشغيل، و5 حالات تقدم الرحلة، و25 اختبارًا للمجسم؛ الأدلة واللقطات في `output/mawrid-system/ux-v7/`. فحص المتصفح جميع المراحل، السابق، التوقف والاستئناف، استعادة المرحلة بعد إعادة إنشاء iframe، واختبار الحساس ثم الإزالة وإعادة الشرح. فُحص عرض 390×842 للجوال و964×976 للمكتب. هذه فحوص وظيفية محددة؛ ليست دراسة استعمال مع محكمين أو تأهيل أداء ميداني.

وضع العرض التلقائي UX V8 يبدأ صراحةً من التجميع ويقرّب كاميرا كل مرحلة خلال 1.1 ثانية، ثم يترك مهلة قراءة بحسب طول النص (20–30 ثانية؛ المراحل الحالية 21–27 ثانية). مجموع القراءة الحالي 190 ثانية، تضاف إليه حركة الكاميرا. إيقاف العرض يحفظ المهلة ويختلف عن إيقاف المحاكاة. التفاصيل والتحكم اليدوي بالكاميرا ومغادرة التبويب وحالات الخدمة توقف العرض حتى متابعة صريحة. تنتهي الجولة بعد الري دون تشغيل اختبار عطل أو إعادة تلقائية، ويوجد بديل نصي عند تعذر المجسم. الأدلة في `output/mawrid-system/ux-v8/`.

تحقق UX V8: 68 مجموعة واجهة، و8 مجموعات مؤقت العرض، و22 حالة تشغيل، و5 حالات تقدم الرحلة، و31 اختبار مجسم وكاميرا نجحت. تحقق المتصفح من الانتقال التلقائي عبر المراحل الثماني، حفظ مهلة الإيقاف، الاستئناف، التقريب، اكتمال العرض دون حقن عطل، مقاطعة التحكم بالكاميرا والتفاصيل، وعرض 389×842 للجوال و961×975 للمكتب. إثبات البناء `output/mawrid-system/ux-v8/plant3d-build-r1.json`؛ التحقق محدد النطاق ولا يشكل دراسة استخدام أو اعتماد إتاحة.

تُسلّم الواجهة الرئيسية في ملف JavaScript كلاسيكي واحد مؤجل التحميل، باسم يتضمن بصمة المحتوى، لتجنّب تعثر إعادة تحميل الوحدات في المعاينة المدمجة. تبقى ملفات المصدر المنفصلة في `client/` للتطوير والاختبارات. بعد تعديلها شغّل `node mawrid-system/build-client.mjs --proof output/mawrid-system/client-build-next.json` من جذر المشروع مع مسار إثبات جديد؛ تحفظ الأداة نسخة وسم الدخول السابق وبصمات المصادر والأصل الناتج وتحدّث `client/index.html`. البناء الحالي موثق في `output/mawrid-system/ux-v8/client-build-r1.json`؛ لا يحتاج المستخدم إلى بناء عند التشغيل.
